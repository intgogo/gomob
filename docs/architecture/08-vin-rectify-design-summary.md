# VIN 数码拓印设计摘要

## 当前权威链路

VIN 日常使用链路中，手机端只负责同步采集、原始落盘、上传、查看和 OCR 触发；标定解析、正射还原、字符规范化与 OCR 代理均在服务端完成。

```text
HLSD8 4160×832 彩色 + RS-D550 640×128 mode25 原始视差×8
  → 点击后跳过3张彩色，至少收3+3帧并在整批中选全局最小回调差（≤100ms）
  → 原始 JPEG/u16 视差、完整 rig/profile 与单调时钟时间戳上传
  → 按 SHA-256 白名单加载 VIN_BF301208.bin 原厂标定
  → 原厂深度反投影 + 私有 RGB 畸变/外参投影 → VIN 承印平面
  → 粗规范图只供逐字符检测（外部算法 method=VINS）
  → 17 字符刚性格架 cᵢ=o+(i-8)·p·u
  → 字符射线在承印平面内细化等步长 3D 基线
  → 双轴统一 25px/mm，一次 Remap 到 5000×678 工作图
  → 原像素中心裁切 (288,39) 得 4425×600 用户/OCR PNG
  → 另出一张同画布副本叠四周毫米刻度尺 + 返回字符串物理度量
  → 用户确认后交外部 VIN OCR
  → 返回与 VIN 等长的 64×128 单字符彩色 WebP + VIN 文本/逐字符置信度
```

宿主原厂文件为 `/root/WindowsR/VIN_BF301208.bin`，固定 `2420B`、version `3`，SHA-256 为 `1a87dc030c50d532503218fbb026a453b2c0fa9b17df5316da60782d8d7bf5d2`。它包含高分 RGB 内参、私有畸变、Euler+T 外参，以及 mode25 深度 K、`49.9893mm` 基线和 `raw disparity×8` 类型，不是“仅深度参数”。服务端按深度序列号 `BF301208`、彩色序列号 `202303111518`、深度 `640×128`、彩色 `4160×832` 完整键加载；标定文件不进入 APK或镜像，生产容器只读挂载到 `/var/lib/gomob/vin_calibration/`。

生产 cv-engine 同时强制 `GOMOB_VIN_FACTORY_CALIBRATION_REQUIRED=true` 与 `GOMOB_VIN_RESTORE_MODELS_REQUIRED=true`。启动监听前必须验证原厂文件大小、version、SHA、bin 内序列号，以及 VIN 还原视觉服务已注入；任一缺失直接拒绝启动，`/readyz` 也返回 503，不能只靠容器 unhealthy 后继续接流量。

VIN 区域与逐字符观测自 2026-07-26 全量下沉外部算法服务（`POST /cv/veh/v1/detect`，`method=VMASK`/`VINS`），本地不再持有检测权重：还原用的几何与最终 OCR 出自同一份模型，不会因两侧版本漂移而对不上。代价是一次还原多两跳远程调用。一致性验收改走离线观测录制回放（`cmd/vinvisionrecord`），报告溯源锚点从模型 sha256 换成录制指纹。

手机生产导航不暴露标定、参数控制和厂商调试入口。网页端尚未补齐 VIN 远程标定会话、交叉验证和版本发布页，因此当前可使用原厂标定，但标定管理职责迁移还未闭环。

VIN 页面固定绑定 RS-D550 深度服务与 HLSD8 彩色服务，不再按页面创建瞬间的 USB 枚举结果回落到 Berxel 或低分辨率内置彩色。USB attach intent 中带授权的 `UsbDevice` 会按型号缓存到对应服务；页面已打开时重插即可重新开流，未连接时保持明确 `NoDevice`，不能把错误相机数据送入原厂标定。

外部 OCR 调用不得发送 `skip_image`。真正的单字符素材来自所选 VIN item 的
`more[].origin_image_data`；`result.image[].vin_detect_image` 是重复的整行图，不进入 App 契约。
Gomob 服务端把厂家 `more` 解析为 `character_crops[]`，只下发位置、字符和经全量解码校验的
`64×128 WebP`，不透传原始 `more`、`alpha_image_data` 或整行图。数量、字符顺序和分数必须
与 VIN 完全一致，损坏时直接失败，禁止拆整行图或用文本生成假切图。App 横向展示真实单字符图、
位置、字符和对应置信度；服务端 `4425×600` 规范化还原图仍单独展示。

## RGBD 快门与时间语义

两颗相机均为独立、无共同硬触发的 `5fps` USB 相机。VINCreator 也不是点击瞬间同时曝光，而是跳过3张 HLSD8、至少收齐3+3帧，在 `±100ms` 内软件配对；Gomob 使用同一 host `CLOCK_MONOTONIC` 回调时钟，并从整批候选中选择全局最小差，不复用点击前或上次快门帧。

当前真机固定回调相位约 `53–55ms`。生产接口按原厂半帧边界使用 `≤100ms`；当前固定 rig 的一致性 harness 使用 `≤70ms`，用于捕获相位或处理管线退化。两者都只约束 native 回调完成时刻；最终像素级重合仍须 PTS/SCR 或同步光学事件证明曝光等效差 `≤25ms`。UI、日志与元数据统一称“回调差”，不得冒充曝光同步或硬同步。

## VINCreator 尺寸契约

- 彩色采集 `4160×832`、深度 `640×128`，两路原始比例均为 `5:1`。
- 双预览槽全宽等高并使用 `5:1` 比例，图像 `Fit` 完整显示且不制造上下黑边；预览不加外层黑框或圆角。彩色 ROI 为 `2dp` 方框、四边内缩 `20dp`，中心 `24dp` 环形准星；不可拍时为红色，框内深度达标后整体变绿。
- 两路显示消费同一个最近邻回调帧对。彩色保持 HLSD8 原始视场；深度不再直接显示 RS-D550 自身视场，而是按服务端只读原厂快照逐像素执行 `disparity×8 → 3D → R/T → FOV → 私有畸变`，投到彩色预览域后做 `3×3` forward splat 和 `abs(cameraZ)` z-buffer。这里只改变显示 Bitmap，拍照缓存、落盘和上传仍是原始 RGBD。
- App 通过 `GET /cv/ocr/v1/vin_preview_calibration` 按完整 `depth serial + color serial + depth profile + color profile` 每页每键获取一次参数；BIN 不进入 APK。Z 反算继续使用原厂全幅 `disparity_focal=1229.20996`，`640×128` 的 `614.60498` 只用于 XY 反投影，禁止混用。用户主标签统一为“深度图”，加载或配置不可用时只在副状态标明“标定加载中/原始”。
- Compose 把实际 `20dp` 框转换成图像域归一化 ROI，绘框与生产投影器共用同一坐标。快门要求 ROI 的 `3×3` 对齐深度覆盖率 `≥95%`、原始连续投影点/ROI 像素比 `≥15%`，且可靠中位距离 `≤400mm`；超过 40cm 明确红框并提示靠近。P10 与 `≥300mm` 比例仍只作诊断；覆盖或点支撑不足时不显示距离，避免用少量残留点给出不准数值。每轮 burst 最终帧必须再次通过同一门，瞬时失败最多重采 6 轮。
- 空间质量与距离达标后，ViewModel 对两路时间戳都前进的唯一帧对做稳定观察：至少 5 帧、跨度 `≥3s`、相邻有效帧间隔 `≤450ms`，ROI 中位距离极差 `≤7mm`（2026-07-28 用户定，原为 `800ms`/`5mm`：太短，抖动没稳住就拍导致还原误差偏大）。期间界面提示“请保持不动”，并在**圆形快门按钮内**以 34sp 大号数字显示 `3→2→1` 倒计时（读秒只此一处，提示条不重复跳数字），读完即拍；中途距离超差则窗口重开、倒计时回到 3。达不到 3 秒时**不做任何超时放宽**，只由手动快门兜底。稳定后自动进入现有 `3+3` burst；手动快门保留为兜底且与自动触发共用一次性认领入口。服务端判废、保存或上传错误锁住自动重拍，只允许用户明确重拍；只有 burst 最终质量瞬时失败会重新武装。
- 规范化还原成功后，App 冻结本次实际上传的 HLSD8 JPEG、与之配对的投影深度图和 ROI 距离指标，再失效预览 generation、清空 RGBD 配对缓存/readiness，并按深度→彩色顺序释放自身双相机 lease；结果态继续显示“深度图 · 本次拍摄 / 彩色图 · 本次拍摄”。“重新扫描”才清旧帧，并以新单调时钟水位按 HLSD8 首帧→80ms→RS-D550 的顺序重启。两服务的引用计数和 600ms 停流代际使用独立短锁，主线程不等待慢速 native stop，旧宽限任务不能关闭新会话。
- 权威还原成功后由同一 ViewModel 工作流 exactly-once 启动 OCR，不通过 Compose 重组触发。识别失败保留规范 PNG，仅允许用户手动重试；成功、识别中或错误状态都不会自动形成循环请求。
- RS-D550 + HLSD8 是 VIN 专用采集设备，连接状态与只读详情入口只放在 VIN 页面顶栏右上角；预览画面不悬浮设备按钮，三维扫描根页也不展示该入口，更不能使用 iHawk 文案代指 VIN 相机。
- 结果首层只展示 VIN、完成/复核、字符数、平均与最低置信字符；`4425×600` 尺寸在图外说明，还原图无覆盖和圆角裁切，17 张单字符图内叠序号、字符、置信度并横滑查看。
- 原厂 `RecMode=2` 对 X/Y 使用同一个 `25px/mm` 标量；不存在纵向单独压缩或经验补偿系数。
- 原厂先生成 `5000×678` 工作图，生产 `scale=1.0`，不会 resize；随后以原像素中心裁切为最终 `4425×600`。修改 Print 尺寸只改变裁切画布，不改变字符像素节距。
- 同批原厂 oracle 字符节距约 `170.28–170.35px`。服务端不再用“120mm → 177.78px”人为推导字号，而由原厂标定恢复的真实平面尺寸乘 `25px/mm` 自然得到同一 VIN 的固定字号。

## 几何不变量

- 第 9 个字符中心落在 `4425×600` 的几何中心，基线固定水平。
- 17 个字符中心等间距；绝对像素节距来自同一承印平面上的真实物理节距和统一 `25px/mm`，不按单张 OBB 宽度缩放。
- 最终坐标自由度只允许平移、旋转和统一尺度；字符基线必须留在深度测得的承印平面内，输出双轴正交且共用同一比例。
- 禁止非等比拉伸、shear、自由仿射、ECC、输出后二次 OBB 或评估前逐图配准。
- `1200×260/64px` 只保留为逐字符检测探针，不是用户输出规格。
- 送检前必须剔除非 VIN 字符：钢印两端的 ☆ 会被 VINS 检成 `-` 类且置信度高达 0.94。
- 逐字符证据不足返回 `text_anchor_unreliable`；客户端只接受响应元数据与完整 PNG chunk/CRC 同时为 `4425×600` 且实际可解码的成功结果。
- 每次服务端裁决必须回传 `device_id`、`color_device_id`、`sync_delta_us` 与非空 `log_id`；已使用标定的成功、倾角、未检出 VIN、字符格架判废还必须回传标定 SHA/version。手机逐项与请求帧对核对，禁止设备串线或旧服务端响应进入结果页。

## 刻度尺与字符度量（2026-07-28）

规范图已是严格 `25px/mm` 的度量图（`1px = 0.04mm`），因此可以在上面叠物理刻度尺——这与 M4.5 之前
「按 OBB 宽度归一」的版本不同，那时尺度随取景变，画 mm 刻度等于把显示尺度冒充物理尺度。

- **两张图，职责分离**：`result_png_base64` 保持干净，是 OCR 输入与一致性/逐字节等价验收的唯一对象；
  `ruler_png_base64` 是同画布副本，四周叠毫米刻度尺，只用于展示与存档。刻度**绝不能**烧进主图——
  那等于改了 OCR 输入，并让全部验收基线一起失效。逐字节等价门 4/4 sha 未变即为该分离的实证。
- **刻度规格**：原点在左上角，上/下边共用 X 读数（0→177mm，自左向右），左/右边共用 Y 读数（0→24mm，
  自上向下）；对边同刻度而非镜像，任取一边读数相同。1mm 次刻度 / 5mm 中刻度 / 10mm 主刻度标数，
  三级用长度与线宽双重区分。黑粗打底 + 白细芯描边，不铺底色带，钢板高光与阴影区都可读。
  尺寸按「缩到手机屏宽仍可读」定，全分辨率下略显粗壮是刻意的。
- **`character_metrics` 契约**：总宽（首字符左缘→末字符右缘）、中心跨距（16×节距）、中心节距、
  字间空隙（节距 − 字宽中位）、字宽/字高中位数，以及逐字符中心坐标与尺寸。mm 与画布 px 双单位，
  恒差 `pixels_per_mm = 25`，客户端逐项校验二者互推，对不上直接失败。
- **尺度基准**：探针像素 → 毫米的换算比例必须取 `grid.pitchMM / anchor.PitchPx`，即 3D 细化后的真实
  物理节距，而**不是**探针铺设时的名义 `mmPerPixel`。后者是 OBB 粗定位给的初值，门限内可差约 1%；
  用错的话用户拿图上刻度尺量到的读数会与返回的数字对不上。
- **成本（2026-07-28 性能 harness 实测，连 166 生产算法）**：HTTP p50 `1022.5 → 1182.1ms`、p95
  `1103.7 → 1219.8ms`，Restore p50 `950.3 → 1047.2ms`，门限 `4000/6000ms` 仍有 3 倍余量，判定正常。
  判废路径 `168.97ms` 不受影响（不生成刻度尺）。**响应体积 `5.2 → 10.5MB`** 是更值得注意的一项：
  手机侧 JSON 解析 `~25ms` + base64 解码 `~34ms`，低端机峰值内存需留意。若要压，展示副本改 JPEG 可降到约 `0.5MB`。

## 验收与现状

权威报告为 `.dev/vin_restore_consistency-factory-bf301208-v3/report.json`。它用四张同一钢牌、倾角 `10.03°–47.64°` 的全分辨率真 RGBD 跑生产 Go Restore，并用录制的外部 VINS 观测回放最终 PNG 的 17 字符锚点；所有样本使用同一固定 `0.36` 相似变换映到探针域比较，禁止逐图配准。

- 4/4 生成严格 `4425×600` PNG，回放的外部 VINS 观测均形成 17 字符锚点，并与 `LA99FRP32G0LTH013` 真值对齐。
- 字符中心最大误差：X `0.91px`、Y `1.92px`；水平角最大 `0.237°`。
- 节距 `170.02–170.77px`，均值 `170.33px`，CV `0.174%`；字高 `236.1–244.4px`，CV `1.42%`，单张最大相对偏差 `2.92%`。
- 物理宽度 CV `0.63%`，倾角跨度 `37.62°`。
- 固定坐标 Edge-F1 median `0.793`、Chamfer median `2.72px`；同批 VINCreator oracle 分别为 `0.532`、`4.53px`。
- 服务端 HTTP 真数据回归中，4/21 张确有 VIN 的样本返回合法 PNG，其余 17 张未拍到 VIN，正确返回 `vin_not_detected`。

BIN parser 已由原厂 native oracle 覆盖：payload version、相机 f64 模型、Euler 顺序、私有畸变、世界到彩色投影、彩色逆投影往返、mode25 深度五个固定 row/column 向量、完整 rig/profile 绑定与损坏拒绝均通过。

实时预览对齐由 `tests/harness/vin_preview_alignment/` 覆盖同一生产 Kotlin 投影器和真机 `cap_036`：61,416 个有效深度点中 67.9% 落入彩色视场，`3×3` splat 后覆盖率 95.4%，宿主 Kotlin P95 小于 30ms，满足 5fps；固定中位深度的 2D 近似 P95 漂移 13.12px，证明不能用固定裁切或平移替代动态投影。探针直接调用生产 `vinPreviewRoi()`，并在 cap_023–036、360/411/432dp 三种宽度上逐项比对 Kotlin/Python：10 个 `restore_ok=true` 样本全部 Ready；cap_023/031/034 即使距离充足仍因覆盖/点支撑不足保持红框；cap_030 只作为 95% 覆盖边界。cap_036 中位距离约 28.9cm、`≥300mm` 仅约 20%，仍正确放行，证明不应增加 30cm 近距离硬门。探针另验证高覆盖约 44.7cm 合成帧必为 TooFar，以及稳定门、手动/自动捕获仲裁、自动识别均恰好触发一次。

Android 16 真机已完成新链路复核：完整 rig 标定 SHA/version 获取成功；确定性 debug 真渲染中，`40.0%` 低覆盖只显示有效率、完全不出现距离，`98.0% / 45.0cm` 显示“距离太远，请靠近至 40cm 以内”且快门禁用，`98.0% / 33.5cm` 显示“请稳住不动”并保留手动兜底。真实自动流程连续 4 次由用户点击“重新扫描”开启新会话，每次均只触发一次捕获和一次识别；稳定距离约 `24.7–27.1cm`，首轮 burst 回调差 `53.758–54.412ms`，均返回严格 `4425×600` 与 17 位/17 张单字符图。最新 `cap_036` 倾角 `40.77°`、中位深度 `245.18mm`、平面 RMS `0.446mm`；双相机各 release 一次并在 600ms 后 stop，无崩溃或 ANR。

手机原始采集改为临时目录完整写入后原子提交：深度必须严格等于 `w×h×2`，设备字符串经 JSON writer 转义，半成品目录不会被后续序号当成有效记录。服务端结果先完成 PNG 实际解码，再提交同目录 `restored.png` 与 `restore.json`；审计文件包含完整 rig、同步差、log ID、标定 SHA/version及结构化判废原因。

2026-07-16 真机稳定性门已闭环：cap_023–029 连续 7 次采集均在第 1 轮收齐 `3+5/3+6` 候选，回调差 `52.517–54.802ms`；6 次生成严格 `4425×600`、17 字符锚点和原厂标定 version 3，1 次正确返回 `vin_not_detected` 且不生成伪 `restored.png`。同一 App PID 连续 3 轮进入 VIN 页、双路首帧、退出和 teardown 全部对称完成，TOTAL PSS 约 `247→293→268MiB`，无单调增长，未出现 native fatal。`eys3d_vendor_cpp` 真机 harness 同时确认 RS-D550/HLSD8 均约 `5fps`、帧路径零 JNI。

## 剩余完成门

- 用 PTS/SCR 或同步光学事件建立曝光时刻映射，证明曝光等效同步差 `≤25ms`；软件回调门不能替代这一物理门。
- 网页端补齐 VIN 远程采集、姿态/角点质量、交叉验证、审核与按完整 rig/profile 发布标定版本的管理闭环。
