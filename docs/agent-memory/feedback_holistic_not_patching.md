# 整体视角验收，不点状打补丁

点云、深度帧、重建网格是整套**几何 + 同步 + 配准链路**的最终表现，
不是靠"这层加个 if、那处 clamp 一下"就能修对的目标。
扫描质量是组合验收，不是单层开发。

**Why:** 单帧深度异常（飞点、空洞、metric 跳变）、一次配准翻转（外参方向反、点云镜像、
配准后两视角对不齐）几乎都不是"出问题那一层"的锅。它的根因往往在更前面的几何或同步：
内外参、反投影坐标系、时间戳偏差、有效距离裁剪、companion 状态行分流、单位换算。
在表层加分支兜住表象，会把真错误埋进去，后面在错误基础上继续打补丁，最终堆成无法解释的屎山，
直接违背[项目魂：扫描必须经得起量测和复现](principle_first_principles_no_compromise.md)。

**How to apply:**

1. 接到深度 / 配准 / 点云反馈时，**先问"整套链路哪一环出了问题"，不要立刻 grep 找最近一层的 patch 点**。
   一帧异常先回溯：采集时间戳是否对齐 → 反投影内参和坐标系对不对 → metric 单位换算对不对
   → companion 状态行分流是否错位 → 配准外参方向 / 手性是否翻转。
2. 改动前先跑整体 harness（`tests/harness/scan_quality`、`device_sync`、`cv_vin_pipeline` 或同等
   dashboard）取 baseline；改动后跑同一 harness 对照，不能只看"那一帧好了没"。
   harness 用法与可判定结论见[harness 强制规范](feedback_harness_mandatory.md)。
3. 拒绝调参式兜底：`if (depth > 8000) depth = 0`、`abs(z) clamp`、给翻转的点云乘个 `-1`
   这种在缺整体画像时等于盲调，把表象压住却没解释根因。先建画像（深度分布 / 配对率 /
   valid 比例 / metric 中位数 / 重投影误差），再做改动。
4. 真因在另一层时就去那一层修，不在出问题的层加假分支兜住——这是
   [整体设计、模块 B 不就绪补 B](feedback_first_principles_design.md) 的同一条纪律：
   不在 A 层加假 fallback 掩盖 B 层缺陷。
5. 验收看链路级指标，不只看单帧：时间同步偏差是否越阈、RGBD 配对率、深度 valid 比例与噪声分布、
   配准后重投影 / 重叠区一致性、缺洞位置是否可解释。每一项都要能讲清来源，不允许"看起来对就过"。
