# VIN 正交还原：彩色正射输出 + 内部签名校正（真机订正 2026-06-22/23）

## What

用户 2026-06-23 明确纠正：**原厂用户可见结果是彩色正射还原图，不是黑白字迹图**。黑白签名图最多作为内部质量闸、水平校正、OCR 辅助候选；服务端 `Restore` / App 回显应返回彩色 PNG。

同一 VIN 不同视角拍摄后，彩色正射图里的字符应大小一致、水平一致、无明显深度透视感。仅把平面投影出来还不够，还要用内部签名图把字符带摆平并按内容宽度归一。

## Why

字斜和透视残留的几何根因：

1. **彩色内参假设错**：之前 `fyc = 2·fyd`。但深度传感器被重度竖直 binning（640×128，`fy≈164` anamorphic，`fx≈614`），彩色(HLSD8 1280×256)不是。实测彩色近方形像素，`fyc≈fxc`。用 `2·fyd` 会留残余竖直透视，字符随拍摄倾角左右渐斜。
2. **平面拟合污染**：固定中心 ROI 会把 VIN strip 上下背景纳入，法向被污染。应先检 OBB，再只在 OBB 区承印面拟合平面。
3. **缺内容锚定**：原厂 `postProcessV3G/picshadow` 一类后处理不是单纯美化，而是把字符带水平化、裁切、规格化。Go 主链必须把内部签名图估计出的旋转/裁切应用回彩色图。

## How to apply

`tests/harness/vin_restore/restore_obb.py` 与 `server/internal/cvengine/restore/` 两端同步：

- **返回形态**：`Restore` 返回彩色正射 PNG；`signatureBinarize(render())` 只作质量闸、水平校正、OCR 辅助，不作为用户可见结果。
- **彩色内参**：`Kc = (2·fxd, 2·fxd, 2·cxd, 2·cyd)`，即 `fyc=fxc`，不要 `2·fyd`。
- **平面拟合 ROI**：用最高分 OBB 的轴对齐 bbox 换算成深度分数 ROI，高度 ×1.25 夹钳定法向；不要中心固定 ROI。
- **彩色后处理**：对彩色 `rect` 生成内部签名图，用黑像素 PCA 估字符带残余角度，旋正签名和彩色，再按黑像素投影取内容框，带上下文边距裁切，宽度统一重采样到 1200，高度按比例夹到 96-260。
- **质量闸**：`SigInkMax=0.25` 仍保留；墨水占比过高返回 `ErrLowQuality`，提示重拍，不返回垃圾图。

验收要看彩色正射结果本身：同 VIN 多角度彩色图中字符位置、大小、水平应一致；黑白签名只作为几何分析和 OCR 辅助信号。去阴影极性/质量闸见 [[finding_vin_signature_binarize_realdevice_2026-06-21]]。

通用教训：双传感器 registration 别假设各轴同比例；正交还原残余透视优先怀疑彩色 `fy`、平面 ROI 和内容锚定，而不是只调二值化。
