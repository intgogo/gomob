# 项目级硬规则 — 开场一问: 有没有历史上下文?

每次对话动手之前, 必答一问: **这个任务有没有历史上下文?** 查 `docs/context/INDEX.md`, 命中哪个模块就先读哪篇 (可多篇), 站在该模块全部已有决策、证伪结论和禁区之上再动手。2026-07-26 起取代旧"动手前必答三问"开场式。

## 为什么

- 项目跨度长、订正链密 (P100R3 双流归因翻案多次、eYs3D mode25 根因订正等), 不带历史上下文动手 = 失忆重启, 极易重走已证伪的路、无意推翻已拍板的决策。项目越大越严重。
- 原始会话 transcript 靠不住: 2026-07-09 环境重置抹掉了 5~6 月全部原始会话, 只有沉淀进 git 的文档能活下来。历史必须活在 `docs/context/`, 不是活在会话记录里。
- 旧三问的精神并入而非废弃: 历史上下文直接回答"我有什么"; "我要什么"查 `TODO.md` 与用户; "我要怎么做"在上下文与 [第一性原则](principle_first_principles_no_compromise.md) 之上推导。

## 如何应用

- **开场**: 扫 `docs/context/INDEX.md` → 读命中模块文档的使命与现状 / 禁区 / 未竟事项, 需要细节再顺指针深入 finding / 架构文档, 不整目录全量加载。
- **动手中**: 方案与某篇"禁区与已证伪路线"冲突 → 停下核对证据; 要推翻已有决策, 必须先向用户复述历史结论再用 AskUserQuestion 确认。
- **收尾**: 产生新决策 / 新证伪 / 里程碑进展 → 增量更新对应 context 文档并刷新"最后更新 / 截至 commit"戳, 可用 `/context-archive` skill 一键归档; 纯执行会话不硬凑。
- **全新领域**: INDEX 无命中 → 按模板新建 `docs/context/<module>.md` 并在 INDEX 加一行。
