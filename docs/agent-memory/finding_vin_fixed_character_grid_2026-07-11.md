# VIN 原厂标定 + 17 字符刚性格架实现固定坐标还原

## Why

同一 VIN 多角度历史数据证明，输出域二次 OBB 不具相似变换等变性，会放大中心和尺度漂移。正确链路是用 VINCHAR 拟合 `cᵢ=o+(i-8)·p·u`，把 17 个字符射线约束在深度承印平面内求等步长三维基线，再从原始彩色图一次 Remap。

`/root/WindowsR/VIN_BF301208.bin` 已经原厂 native 逐字段确认：它是 2420B little-endian v3 标定，包含高分 RGB 内参、私有畸变、Euler+T 外参，以及 mode25 深度 K、49.9893mm 基线和 `raw disparity×8` 类型；SHA-256 为 `1a87dc030c50d532503218fbb026a453b2c0fa9b17df5316da60782d8d7bf5d2`。旧“只含深度参数”“BF301208 外参必然无效”的结论来自把 f64 错扫成 f32，已撤销。

VINCreator `RecMode=2` 对双轴统一使用 `25px/mm`，先生成 `5000×678` 工作图，生产 `scale=1.0` 不缩放，再中心裁切 `(288,39)` 得最终 `4425×600`。不存在纵向单独压缩。旧“120mm → 177.78px”是人为字号推导；同批原厂 oracle 的真实字符节距约 `170.28–170.35px`。

当前 `.dev/vin_restore_consistency-factory-bf301208-v3/report.json` 用四张全分辨率真 RGBD 验证：4/4 输出 `4425×600`，中心最大误差 X `0.91px` / Y `1.92px`，水平角最大 `0.237°`，节距 `170.02–170.77px`、CV `0.174%`，字高 `236.1–244.4px`、CV `1.42%`、单张最大相对偏差 `2.92%`，倾角跨度 `37.62°`，物理宽度 CV `0.63%`。固定坐标 Edge-F1 median `0.793`、Chamfer median `2.72px`，优于同批 VINCreator oracle 的 `0.532/4.53px`。

## How to apply

- 最终用户/OCR PNG 固定 `4425×600`；`5000×678` 只是原厂内部工作画布。成功响应必须同时校验元数据和 PNG IHDR。
- 规范化只允许平移、旋转、统一 `25px/mm`；字符三维基线必须留在深度承印平面内，双轴正交。禁止二次 OBB、shear、非等比拉伸、ECC 和评估前逐图配准。
- `1200×260/64px` 只供 VINCHAR 检测/评估；同一 VIN 的绝对字号来自原厂标定恢复的真实物理节距，不按单张内容宽度硬拉。
- 深度输入是 mode25 原始 u16 LE `disparity×8`，不是 metric mm。原厂反投影使用 `z=f·B/(raw·0.125)`，世界轴顺序为“竖直向上、水平向右、Z”。
- 标定按深度序列号、HLSD8 序列号和两路流档位完整绑定；当前生产键为 `BF301208 + 202303111518 + 640×128 + 4160×832`，文件由服务端 SHA 白名单加载，不进入 APK。
- 手机只采集、上传、显示和触发 OCR，不暴露标定管理；网页仍须补齐远程采集、交叉验证、审核和版本发布。
- 两颗 5fps 相机无硬触发。日常快门跳过3张彩色、至少收齐3+3并取整批全局最小回调差 `≤100ms`；最终完全重合仍须 PTS/SCR 或同步光学事件证明曝光等效 `≤25ms`。
